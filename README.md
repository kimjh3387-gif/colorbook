# 색칠공부 변환기 (Coloring Page Maker)

사진을 올리면 색을 다 빼고 **색칠공부(coloring book) 윤곽선 그림**으로 바꿔주는 정적 웹 도구.
서버가 없다 — 업로드한 이미지는 브라우저 안(Canvas)에서만 처리되고 어디로도 전송되지 않는다.

아이들용 단순한 그림부터 어른용 정교한 컬러링북까지 **단순화 슬라이더 하나로** 커버한다.

## 배경 지우기 (기본 켜짐)
숲 배경 애니 장면처럼 배경이 있으면 어떤 모드든 배경 텍스처가 선으로 딸려온다. 변환 전에 U²-Net-p(4.6MB, Apache-2.0)로
주요 피사체 마스크를 뽑아 배경을 흰색으로 밀어낸 캔버스를 세 모드 공통 입력(`activeSource`)으로 쓴다. 원본당 한 번 계산·캐시.
- 320×320 고정 입력, 마스크 0.15~0.85 구간을 0~1로 펴서 경계 뿌옇게 남는 것 방지
- 한계: 경량 모델이라 "주인공 하나" 위주 — 옆의 두 번째 캐릭터는 같이 지워질 수 있다(애니 장면의 드래곤 실측)
- **함정**: 원본 ONNX의 MaxPool 33개가 `ceil_mode=1`이라 WebGPU 실행기가 거부한다
  (`using ceil() in shape computation is not yet supported for MaxPool`). 320 입력은 모든 단계가 짝수(320→…→10)라
  결과가 같으므로 플래그를 0으로 바꿔 저장했다(CPU 결과 차이 0 검증). 모델을 다시 받으면 이 처리를 다시 해야 한다.

## 변환 방식 (v4, 2026-09-11 밤) — "선화" 하나
사용자 실측 결론: 검은 윤곽선이 있는 일러스트에선 선화(어두운 픽셀 그대로)가 압도적이고, 학습된 엣지 모델(PiDiNet)은
없는 선을 "그리는" 순간 울퉁불퉁해지고 봉제선까지 끌어와서 퀄리티를 망친다. 그래서 **AI 윤곽·기본(그래디언트) 모드와
모드 토글을 전부 없애고**, "원본에 있는 것만 그대로 뽑는" 세 층을 합친다 (`render`):

| 층 | 원리 | 조절 |
|---|---|---|
| 1. 검은 선·검은 면 | RGB 최대값 < `어두움 기준`(기본 150)인 픽셀. 세선화 안 함(붓 굵기 유지), 닫기 r=1로 핀홀 메움 | 어두움 기준, 단순화(흐림 ×0.25) |
| 2. 실루엣 선 | 배경 분리 마스크(U²-Net-p)의 테두리. 모델 마스크라 매끈함 | 체크박스 |
| 3. 색 경계 선 | RGB 3채널 그래디언트 → NMS → 히스테리시스. 기준은 **절대값**(상한 130−강도×0.9)이라 그림자(색 거리 20~40)는 항상 빠지고 볼·무늬(150+)는 항상 잡힘 | 체크박스 + 강도(기본 70) |

2·3은 **1의 6px 이내엔 안 얹는다**(`nearInk`) — 일러스트에서 윤곽선 바깥에 실루엣이 한 줄 더 생기거나 검은 선 양옆에 색 경계가 붙는 이중선 방지.
실측: 삐삐+모래두지에 색 경계를 켜도 검은 비율 6.93%→6.95%로 거의 안 변함 = 겹침 억제가 먹힘.
인형 피카츄는 실루엣 없이 색 경계(노랑↔흰 배경)만으로도 흔들림 없는 윤곽 + 검은 귀 끝·눈·입이 나온다. 볼(펠트라 경계가 흐림)은 강도 70부터.

### 색칠 다듬기 (v6) — 색칠공부 조건: 닫힌 영역 + 칠할 수 있는 크기
드로잉(원본을 닮게)과 색칠공부(칠하기 쉽게)는 목적이 반대다. 색칠공부는 선이 닫힌 영역을 만들어야 하고 영역이 적고 커야 한다.
- **끊긴 선 잇기**(`bridgeGaps`, 기본 12px): 1px 뼈대에서 끝점과 진행 방향을 구해 정면→±20°→±40° 순서로 쏘고, 처음 만나는 선까지
  직선(반지름 1.5)을 긋는다. 반경 안 아무 선에나 붙이면 나란한 이중선이 사다리처럼 엮여서 **방향으로 쏜다**. 자기 선 두께를 벗어난 3px부터.
- **작은 조각 정리**(`fillTinyRegions`, 기본 150px²): 선으로 갇힌 흰 조각 중 작은 것을 선으로 메운다. **두 조건을 다 만족해야** 메움:
  (1) 테두리에서 2px 이상 떨어진 픽셀이 없다(폭 5px 미만) (2) 둘러싼 상자의 긴 변 ≥ 짧은 변×3(길쭉하다).
  처음엔 넓이만 봤더니 **눈 하이라이트·이빨이 메워졌다**(실측 회귀). 하이라이트는 폭 5px라 (1)은 통과하지만 동그래서 (2)에서 걸러진다.
- "흰 영역 개수"는 지표로 애매하다 — 틈을 이으면 큰 영역이 갈라져 개수가 늘어난다. 눈으로 확인할 것.

### 선화 튜닝 함정
- **`어두움 기준` 110은 점선이 된다.** 작은 원본을 1200으로 키우면 안티앨리어싱 때문에 선 픽셀 최대값이 120~150까지 올라간다. 기본 150.
- **흐림 반경 1.5(단순화 3 × 0.5)도 점선을 만든다.** 가는 선이 옅어져 기준 아래로 내려감. 단순화 × 0.25로 낮췄다.
- **열기(침식→팽창) 연산은 1~2px 선을 통째로 지운다.** 닫기(팽창→침식, 반경 1)만 쓴다.
- PiDiNet 관련 코드·모델은 커밋 `800c9fb`까지 있다. 복구할 일 있으면 거기서.

## 컨트롤 (v5)
설명문은 패널 공간을 다 차지해서 **`?` 아이콘 툴팁**(`.help[data-tip]`, hover/focus)으로 옮겼다.
슬라이더는 1 단위(굵기·단순화 0.25), 굵기 최대 30. `선 진하기`(5~100 → 선 색 255×(1−v/100))와
**용도 프리셋**(색칠용: 굵기 1/진하기 100, 따라 그리기용: 0.5/30 — 연한 회색 가는 선 위에 펜으로 덧그리는 용도).

## 원본·제목 배치 (v7) — 결과 그림 위에 직접
결과 카드 툴바의 `🖼️ 원본 넣기`와 제목 입력. 원본 썸네일과 제목은 **결과 캔버스에 그려 넣는다**(`drawOverlays`, 지우개 자국 다음에)
→ PNG 다운로드·크게 보기·인쇄 전부에 그대로 들어간다. 화면의 점선 박스(`#ovOriginal`, `#ovTitle`)는 드래그·크기조절 손잡이일 뿐이고
글자 쪽 DOM은 투명. 좌표는 캔버스 비율(`layout`)이라 이미지를 바꿔도 자리가 유지된다.
- 크기조절은 **네 모서리 전부**(반대쪽 모서리 고정, 비율 유지). 처음엔 우측 하단만이었는데 사용자가 전부 요구.
- 손잡이 위치는 `canvasGeometry()`(object-fit: contain 레터박스 보정)로 놓고, 창 크기가 바뀌면 다시 놓는다.
- 지우개 획이 원본 위를 지나가면 흰색으로 덮이므로 획이 끝날 때 전체를 다시 그린다.
- **여백 추가**(`marginBox`): 그림 바깥에 흰 여백(아래/오른쪽/왼쪽/위/사방, 5~80%)을 붙여 원본·제목 놓을 자리를 만든다.
  그림이 캔버스를 꽉 채우면 원본이 그림 위에 겹칠 수밖에 없어서(사용자 실측). 지우개 자국·원본 위치는 최종 캔버스 비율이라
  여백을 바꾸면 자리가 밀린다 — 여백 먼저 정하고 배치.
- 처음(v5)엔 인쇄 직전에 종이 위에서 배치하는 모달이었는데, 작업하면서 바로 보고 PNG에도 들어가는 게 낫다는 사용자 판단으로 옮겼다.

## 인쇄
`🖨️ 인쇄 / PDF 저장` → 결과 캔버스(원본·제목 포함)를 `#printSheet`의 `<img>`에 넣고 `window.print()`. A4 한 장에 contain.
- **함정 1**: src를 넣자마자 `print()`를 부르면 미리보기가 빈 종이 (data URL 디코딩이 안 끝남). 결과가 그려질 때마다 미리 채워두고(400ms 디바운스), 버튼은 `img.decode()`를 await.
- **함정 2**: 화면용 `.print-sheet { display:none }`이 CSS 파일에서 `@media print` 블록 **뒤**에 있으면 인쇄용 `display:block`을 덮어 빈 종이가 된다(실측, v5 회귀). `!important`로 박아뒀다.
- **용지 방향은 CSS에 고정하지 말 것** — `@page { size: A4 portrait }`를 박았더니 인쇄창 레이아웃 옵션이 잠기고 가로 그림이 세로 용지에 작게 찍혔다.
  `#printPageStyle`에 JS가 `@page { size: A4 <방향> }`을 매번 넣는다. 패널의 `인쇄 용지 방향`(자동/세로/가로), 자동이면 결과 캔버스가 가로로 길 때 가로.
